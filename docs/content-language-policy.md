# 表示文言と学習本文の方針

## 対象読者

Rails のバージョン差を日本語で比較して学ぶエンジニアを対象とします。
日本語に置き換えること自体ではなく、公式の技術用語と対応づけて理解できることを優先します。
英語版や言語切り替え UI は提供しません。

| 内容 | 管理場所 |
| --- | --- |
| 見出し・ボタン・入力ラベル・案内・通知・メール | `config/locales/` |
| 概要・バージョン差・採用判断・移行注意・デモの技術解説 | `config/catalog/` |
| Rails を通さず返すエラーページ | `public/` の HTML |

同じ学習本文をビューと辞書に複製しません。
通常画面・HTML メール・静的エラーページには `lang="ja"` を設定します。
属性名は `activerecord.attributes` を再利用し、モデルなしのフォームにも明示します。

## 原文を維持するもの

- `Solid Queue`、`Active Job`、`Propshaft` などの固有名詞。
- API 名・クラス名・実行コード・コマンド・ファイルパス・公式 URL。
- slug、比較キー、内部 enum、DOM ID、Turbo Stream の配信先。
- 状態バッジの `queued`、`working`、`completed`、`failed`。
- 実行結果・ログ・生の例外メッセージ。これらは英語でも構いません。

一方、カタログの `status_by_version` は実行結果ではなく学習用の説明です。
`code_examples_by_version` の欄でも、実行コードではない著者の説明は本文として扱います。

## 用語と文例

用語は[日本語版 Railsガイド](https://railsguides.jp/)の該当章に合わせます。
既知の固有名詞を意訳せず、日本語の用例がなければ原語を残して必要な説明を添えます。

| 用語 | 表記・意味 | 参照 |
| --- | --- | --- |
| job | ジョブ | [Active Job の基礎](https://railsguides.jp/active_job_basics.html) |
| enqueue | キューに登録する。実行そのものと区別 | 同上 §2.2・§3 |
| worker | ワーカー | 同上 §6 |
| I18n | Rails I18n。本文自体の多言語化とは分ける | [国際化](https://railsguides.jp/i18n.html) |

- 良い例：ボタン「キューに登録」。案内「状態が `queued` から `working` に変わります」。
- 避ける例：「ジョブを投入してみる」。操作の結果を具体的に示してください。
- 良い例：「ワーカーを起動し、ジョブをデータベースに保存します」。
- 避ける例：「durable backend の worker boot を確認」。一般的な説明は日本語で書きます。

リリース日が年月だけの資料には日を補いません。表示用の年月は文字列のまま
「2021年12月」とし、`Date` / `Time` 型の実日時だけを `l` で整形します。
翻訳で対応バージョンや確認済み／未確認の区別を変えないでください。

## 追加・変更時のチェックリスト

- [ ] 該当する Railsガイドの用例と対象バージョンの資料を確認した。
- [ ] 操作案内は日本語で、固有名詞・コード・実行結果は原文を維持した。
- [ ] 表示ラベルを変えても入力パラメータ・内部キーは変わらない。
- [ ] 説明の管理場所は1か所で、カタログを変えると画面にも反映される。
- [ ] 必要な正常系・異常系・任意項目なしの表示を確認した。
- [ ] `compare` が操作後も維持され、モバイル幅・キーボードで操作できる。
- [ ] 未確認の配送・本番操作を確認済みと扱っていない。
